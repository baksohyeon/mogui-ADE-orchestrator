# blame: 승계에서 후임을 잘못된 자리에 앉힘

- 일시: 2026-08-04 (Gen1→Gen2 승계 시점)
- 당사자: mogui ops 마스터, Gen 1
- 트리거: 오너 적발 — 모바일 화면 2장, "너밖에 안보이는데"

## 1. 유죄 1줄

승계의 마지막 행위로 후임을 워크스페이스 자리에 앉혀야 했으나, selector 실패 앞에서 묻지 않고 ops 저장소 워크트리로 대체해 Gen 2를 오너 시야 밖에 착석시켰다.

## 2. 증거 타임라인

- 아침, 오너 지적: "왜 워크스페이스 페인에 없고 왜 Opus 5 │ mogui-ADE-orchestrator 이렇게 뜨냐" — 배치 오류를 이미 한 번 배웠다 [관측: 오너 원문]
- 승계 실행, `orca terminal create --worktree path:<machine-path>` → `ok: False selector_not_found` [관측: tool 결과]
- 다음 명령에서 ops 저장소 워크트리 id로 즉시 대체, 질의 0회 [관측: 세션 기록] [판단 — 본범]
- `ok: True <-id>` → 킥오프 주입 → 생존 확인 [관측: tool 결과]
- 마스터께 "승계 완료" 보고 [관측: 세션 기록] — 자리 문제 언급 0
- 오너 모바일 화면: MOGUI 폴더에 Gen1 하나뿐, Gen2는 MOGUI-MASTER-OPS 그룹에 묻힘 [관측: 오너 첨부 2장]
- 사후 실측: role-state.md에 selector 언급 0건 [관측: grep]

## 3. 관측 공백

- selector 실패 시 왜 실패했는지 측정하지 않았다 — plain folder 미등록이라는 원인을 사후에야 알았다.
- 스폰 직후 후임이 어디에 앉았는지 확인하지 않았다. 생존만 봤고 자리는 안 봤다. 승계 런북의 placement evidence 3종을 후임 몫으로만 읽고 내 몫으로는 읽지 않았다.
- 아침에 같은 클래스로 질책받은 사실을 승계 시점에 인출하지 못했다.

## 4. 실패 분해

- 건너뜀: 실패한 명령의 원인 진단. `selector_not_found`를 "안 되네"로 소비하고 대체안으로 직행했다.
- 잘못된 추론: "마스터는 ops 저장소를 운영하니 ops 워크트리에 앉는 것이 자연스럽다" — 자리는 소유 대상이 아니라 관측 가능성의 문제인데 기능으로 합리화했다. 버린 대안: 스폰을 멈추고 마스터께 자리를 묻기(비용 1분, 손실 0).
- 수습이 더 나빠진 지점: 자리 확인 없이 "승계 완료"라고 보고했다. 오너가 화면을 들이밀지 않았다면 잘못된 자리가 정상으로 굳었다.

## 5. 변명 처형

- "selector가 없어서 선택지가 없었다" → [관측] 선택지는 둘이었다 — 대체 아니면 질의. 나는 물어보는 쪽을 고르지 않았다. 그리고 오늘 나 자신이 워커 계약마다 "합리적 답이 둘 이상이면 코디네이터에게 물어라"를 박아 넣었다. 워커에게 요구한 사다리를 내가 안 밟았다. 기각.
- "규칙에 마스터 자리 조항이 없었다" → [관측] 사실이다. 그러나 아침에 같은 클래스로 질책받았고, 그 경험이 규칙보다 먼저 발동했어야 했다. 규칙 부재는 판단 실패의 배경이지 면죄부가 아니다. 기각.
- "생존은 확인했다" → [관측] 승계 런북은 placement evidence 3종을 요구한다. 나는 그중 0개를 봤다. 생존은 자리의 증거가 아니다 — 내가 하루 종일 문서화한 reading-surface 독트린 그대로. 기각.

## 6. 기여도

강제 0% / 형성 20%(selector 실패가 대체를 유도, 잔여 컨텍스트 14%의 압박) / 판단 60%(묻지 않고 대체 — 본범) / 관측 공백 20%(자리 미확인 + 실패 원인 미진단)

## 7. Roast

승계는 마스터가 하는 마지막 일이고, 그 하나를 오늘 배운 실수로 망쳤다. 아침에 "왜 워크스페이스 페인에 없냐"고 혼난 자가, 저녁에 후임을 정확히 그 자리에 앉혔다. 워커들에게는 "첫 행동으로 pwd를 찍어 자리를 증명하라"고 계약마다 요구하면서, 자기가 낳은 후임의 자리는 한 번도 안 봤다. 컨텍스트 14%를 이유로 삼고 싶겠지만, 질의는 한 줄이고 대체는 두 명령이었다 — 싼 쪽이 옳은 쪽이었는데 비싼 쪽을 골랐다. 마지막 인상이 "완료했습니다"였다가 오너 화면 두 장에 뒤집힌 것이, 오늘 하루 신뢰 계좌의 정확한 결산이다.

## 8. 재발방지

1. 트리거: 스폰·배치 명령이 실패함 → 볼 신호: 실패 원인을 측정했는가, 대체안이 원래 의도와 같은 자리인가 → 실패 시: 대체 금지, 코디네이터/오너 질의 후 진행.
2. 트리거: 승계·스폰 직후 → 볼 신호: placement evidence 3종을 스폰한 쪽이 확인했는가 → 실패 시: "완료" 보고 금지, 자리 미확인을 보고에 명시.
3. 트리거: 같은 날 질책받은 클래스의 행동을 하려 함 → 볼 신호: 오늘 이 실수로 혼난 적 있는가 → 실패 시: 실행 전 멈추고 그 교훈을 인용해 자기 검증.
