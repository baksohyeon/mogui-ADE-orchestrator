`template-apply` collects, at plan time, which documented placeholder tokens the planned write set still carries and refuses the write while any of them lacks a supplied value. `plan_actions` already excludes `SKIP_SUBSTITUTE_PATHS`, instance-owned paths, and refused paths from the write set; `missing_placeholders` reads only what survives that filter, unions the tokens found with the supplied keys, and reports the gap per key with the relative paths that need it. A dry run without `--placeholder OPS_REPO=...` against a founded install used to exit 0, write every file, and leave `OPS={{OPS_REPO}}` in `scripts/dispatch` for `test-dispatch-multi-vendor-host.sh` to trip over later as a `FileNotFoundError`; it now prints the missing set and exits 2, the same could-not-decide status `template-check` already uses for an unreadable input. `--write` carries the same refusal to stderr before the confirmation prompt and writes nothing. A supplied key that no planned file uses stays unreported, and a token in a skipped or refused file is never counted toward the gap.
