A contract may now open with a typed front matter block (`tier`, `runtime`, `repo` required; `budget`, `writes`, `standing_rules` optional), parsed and validated in `DispatchGate.check` before any Orca call. An unknown key, a missing required key, or a malformed line all refuse with `CONTRACT_FRONT_MATTER`; a declared tier or runtime that does not match the dispatch refuses with `CONTRACT_TIER_MISMATCH` or `CONTRACT_RUNTIME_MISMATCH`, a runtime the policy does not carry for that tier refuses with `RUNTIME_NOT_ELIGIBLE`, and an unrecognized `standing_rules` name refuses with `STANDING_RULE_UNKNOWN`; a contract with no block only warns (`CONTRACT_FRONT_MATTER_MISSING`) this release. The validated object is exposed on `GateDecision.front_matter` and in the CLI's JSON (never the raw form behind a refusal), so `master-ops/scripts/dispatch` reads named `standing_rules` blocks straight off the gate's own recorded check instead of re-parsing the contract, and appends each block's text to the dispatched spec, checking the never-overwritten instance overlay `master-ops/config/standing-rules.overlay.md` first and the template-layer `master-ops/rules/standing-rules.md` second, so the overlay's own text wins when both name the same block. Five canonical blocks ship: `headless`, `ack-token`, `placement`, `voice`, `pr-house`.
