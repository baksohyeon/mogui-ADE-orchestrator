- The read-proof token's `config/gitleaks.toml` allowlist entry moves from `regexTarget = "match"` with the unanchored regex `\back-[0-9a-f]{12}\b` to `regexTarget = "secret"` with the anchored regex `^ack-[0-9a-f]{12}$`. Measured: the old entry cleared `ACCESS_TOKEN="ack-<12 hex>-real-secret"` entirely, because a match-target regex is compared against the whole matched secret and the unanchored token shape matched as a substring of it. The new entry clears only a secret that IS the token.
- `master-ops/scripts/test-redaction-read-token.sh` no longer hardcodes the scan two directories above itself. It walks up from its own directory looking for a sibling `scripts/redaction-scan.sh`, which an install finds one level up (ships from a top-level `scripts/`) and the authoring template finds two levels up (ships from a nested `scripts/`), and SKIPs only once every level to the filesystem root has been tried. Its assertions now measure the three cases above: a token-only file is not flagged, the prefixed real secret is still flagged, and a fake AWS key sharing a line with the token is still flagged.
- `master-ops/scripts/template-check` gains an `advisories` key, which never fails the check. It reports when an install's `config/gitleaks.toml` exists but has no `[[allowlists]]` entry matching the read-proof-token shape above, with the exact TOML block to paste; `config/gitleaks.toml` stays seat-owned, so the template still never writes it. `master-ops/onboarding/upgrade.md` documents the check and the block. The onboarding generator does not render `config/gitleaks.toml` for new installs, so there is nothing to update there.
- `template_manifest.py`'s `_is_normalized` rejects an `instance_owned` entry containing a null byte, the same way `template-apply`'s `normalize_rel` already does, so malformed metadata cannot pass manifest validation.
- `template-check`'s read-token advisory now also flags a surviving legacy `[[allowlists]]` entry (any entry whose regexes mention the `ack-` shape but is not the anchored `regexTarget = "secret"` form), telling the install to replace it rather than paste the new block beside it; it also reports a non-failing "could not inspect" advisory on an unreadable or malformed `config/gitleaks.toml`, and treats a non-list `allowlists` value as no entries instead of raising. `test-redaction-read-token.sh` adds a fourth row: the token written as a quoted key assignment (`access_token = "ack-<12 hex>"`) is still flagged, since the assignment rule's secret is the whole assignment, by design — a token belongs only in a worker's completion message, never in a committed file.
