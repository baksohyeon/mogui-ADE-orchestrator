`WorkerReaper._check_worktree_safe_to_remove` (`src/master_runtime/core/worker_reap.py`) reads `git status --porcelain`, which never lists ignored files, so a worker worktree whose `.gitignore` covers rendered media lost that media with `git worktree remove`. `reap()` now runs a third check once the clean and merged checks pass: `_ignored_media(worktree_path)` runs `git status --porcelain --ignored --untracked-files=all -z` and matches its `!! ` paths against `IGNORED_MEDIA_SUFFIXES` (`.mp4 .webm .mov .mkv .wav .mp3 .flac .png .jpg .jpeg .gif .webp .pdf`, case-insensitive), recorded as `measurements["worktree_ignored_media"]`. A clean, merged worktree holding matching ignored media is left in place with `worktree_left:<path>:ignored_media:<count>`; `scripts/worker-reap --remove-ignored-media` (and the matching `WorkerReaper`/`reap()` parameter, both defaulting to off) overrides that positive count and removes the worktree anyway. A git failure during the scan leaves the worktree in place with `worktree_left:<path>:ignored_media_unmeasured` regardless of the flag. An ignored file outside the suffix list, such as a stray `.pyc`, does not block removal. `docs/runbooks/worker-reap.md` documents the new condition and measurement key.
