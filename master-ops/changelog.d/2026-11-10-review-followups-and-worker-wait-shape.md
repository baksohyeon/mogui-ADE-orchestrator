- `test-product-path-guard.sh`'s `run_worker()` now pins `MOGUI_PRODUCT_GUARD_FAIL_CLOSED=0`, like the other runners in the suite, so the allowed interpreter-read case in worker mode still holds when the suite runs with `MOGUI_PRODUCT_GUARD_FAIL_CLOSED=1` exported from the caller's environment.
- `scripts/memory-link-check`'s `FENCE_RE` now matches a fence opener or closer indented by at most three spaces, matching the CommonMark rule that four or more spaces makes an indented code block, not a fence; a four-space line that merely looks like a fence no longer swallows the links that follow it.
- `docs/runbooks/memory-link-check.md` and `docs/runbooks/product-path-guard.md` are narrowed: the memory-link-check doc states exactly which fenced and inline-code shapes the checker handles (and the two it does not), and the product-path-guard doc states that an empty or unset `MOGUI_WORKER_WRITE_ROOT` means master mode, not a refusal, and that `dispatch` always sets it to a non-empty absolute path on the panes it creates.
- `scripts/worker-wait`'s `_worker_list` now raises `WorkerListError`, naming the shape it got, when a `worker-list` result parses but is not a dict or has no `workers` key, instead of silently reading it as zero dispatches; `{"workers": []}` still reports a genuinely empty run (issue #219).
