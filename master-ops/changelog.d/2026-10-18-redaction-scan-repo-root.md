`scripts/redaction-scan.sh` fixed its working directory to its own repository, so a caller in another repository that ran it with `--staged` scanned this repository's empty index and read `clean` with `files=0`; measured when a gate wired this script as its staged credential lane and that lane scanned nothing while gitleaks run directly on the same staged file found the planted key. `--repo-root PATH`, or `REDACTION_REPO_ROOT` for callers that cannot pass a flag (the flag wins when both are set), names the repository to scan instead: every `git` call and every finding path is relative to it. Unset, the target stays the script's own repository, exactly as before. The rules — `config/gitleaks.toml`, the legacy-allowlist check, and the organization rules translation — keep resolving against the script's own repository regardless of the target, and both summary lines now carry `root=<target top level>` so a caller can see what was scanned. A target that is not inside a git work tree prints one stderr line naming the flag and the value and exits 2 before any scan.
