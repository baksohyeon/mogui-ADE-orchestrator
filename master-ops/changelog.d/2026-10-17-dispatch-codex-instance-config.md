`master-ops/scripts/dispatch` reads two optional instance runtime config keys for codex workers. `codex_reasoning_effort` (`minimal`, `low`, `medium`, `high`, `xhigh`, or `max`) replaces the hard-coded `xhigh` in both the launch line and the start-screen footer check, and `codex_bypass_approvals_and_sandbox: true` appends `--dangerously-bypass-approvals-and-sandbox` as an explicit operator opt-in and prints a warning on stdout; the per-dispatch `host_diversity_audit` ledger line records the choice as `codex_bypass` (`true` or `false`). Only a codex dispatch reads the keys. Absent or null keys leave the launch line unchanged, and an invalid value stops a codex dispatch with exit 2. An installation that chose another effort or the bypass can now take template upgrades whole without losing that choice. Measured 2026-10-24 on codex-cli 0.164.0 with one unreviewed hook in a scratch codex home directory: the "Hooks need review" modal appears the same with and without `--dangerously-bypass-approvals-and-sandbox`, so a bypass launch still goes through the hooks vet.
